## Reuse rules

- Use the sample to ask whether the new report covers every required and relevant area at adequate depth: front matter, background, requirements, analysis/design, architecture, implementation, interface, testing/evaluation, limitations, conclusion, references, and appendices where they apply.
- Use the sample's visual style only when the user asks for it or the selected template/profile supports it.
- Derive the actual outline and figure/table inventory from the new assignment, rubric, profile, and project sources. Record each planned heading and visual in that project's matrices; number of rows varies by project.
- Do not force sample-specific tables, screens, routes, identity fields, claims, signatures, metrics, or images into a new report. Do not copy StrongWine content or assets.
- A reviewer confirms the project matrix is complete against the assignment/rubric/profile and has been depth-checked against this example. The readiness checker verifies the matrix-to-DOCX match; it cannot detect a requirement omitted from the matrix.
