# VietLex revision and reusable report pipeline

Authority: current user correction, the selected HCMUNRE report guide, and the read-only VietLex source tree. The user explicitly authorizes adding, changing and removing scripts, skills and Markdown where needed, and removing redundant material.

## Scope

- Preserve v11 and produce v12 with a logical data model using UML class notation (including multiplicities, embedded records and references), activity and state diagrams grounded in actual source.
- Improve Vietnamese academic prose, causal reasoning and section hierarchy; preserve citations, factual limits, approved cover/front matter, captions and Word fields.
- Reuse WordAssistant CLI operations for native fields, rendering, validation and evidence. Add only parameterized helpers for gaps; keep subject facts and institutional rules in workspace plans/profiles.
- Add a semantic review plan that checks required models and argument coverage before delivery. Counts and formatting cannot certify content completeness.
- Cleanup only explicitly inventoried redundant generated files/caches after final artifacts and their evidence are stable. Preserve source inputs, final evidence and reproducibility inputs.

## Acceptance

1. Data diagrams reflect account/session/interaction and research workspace records in current source, with no invented ORM classes or SQL foreign keys.
2. Each added diagram has editable source, current source hashes, a Word caption, and a substantive explanation.
3. Chapter hierarchy follows the reasoning; redundant headings are consolidated and jargon is explained in Vietnamese. New prose adds analysis rather than filler or unsupported results.
4. A reusable plan-driven revision helper rejects stale hashes/ambiguous anchors and preserves citations/fields. Pipeline audit rejects missing semantic reviews and models; meaningful tests cover those failures.
5. v12 native Word delivery/profile/render/visual QA and integrity/provenance are hash-bound; readiness reports remaining external review limits truthfully.
6. Documentation and skill use one canonical runbook and existing helpers; cleanup has exact paths, hashes and a receipt. No commit, push or paid call.

Graph tools are unavailable in this session; repository review uses source and targeted Git diffs.
