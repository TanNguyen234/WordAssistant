## Root cause

Long conversation history increased the risk of picking up an old candidate or repeating a superseded instruction, but it was not the main cause. The workflow lacked hard gates for each user requirement: a frozen brief tied to the current DOCX hash, visible TOC parity, embedded-image-to-caption parity, explicit diagram/screenshot distinction, citation/claim evidence mapping, and a per-requirement acceptance record. Broad booleans and stale project pointers allowed concrete omissions to be described as complete. Repeated user corrections exposed these missing gates.

## Workflow changes

- Added a workspace `task-brief.md` handoff with controlling sources, screenshot rules, current input/output hashes, current QA, blockers and next action.
- Added `acceptance-crosswalk.csv` categories and evidence file hashes bound to the current DOCX.
- Readiness now compares every real Word heading and visible TOC entry, counts embedded images by caption, inventories uncaptioned logos/tables, and keeps runtime capture, content/source and submission gates separate.
- Runtime screenshots require visible, non-headless browser clickthrough from the site UI. Each page records route/URL, click path, HTTP/document status, console state, timestamp and image hash. Direct-route, local-file and headless captures fail when user-style capture is required.
- Recorded all 43 WARN findings from the current integrity audit in `integrity-warning-dispositions-clickthrough-v12.csv`.
- Fixed two false negatives found when applying the new checker to the actual final DOCX: a `w:tab` paragraph tab stop was mistaken for the visible TOC page-number separator; Word's SEQ result split caption numbers into spaced runs such as `2. 1 .`. The checker now reads only run-level page-number tabs and normalizes sequence punctuation. Added regressions for both.
- Updated the runbook for Word field updates: recheck styles after Word saves fields because explicit Heading 3 formatting can change.
